# 詳細な使い方

[README](../README.md) / [利用ガイド一覧](README.md)

デバイス設定、音声の調整、設定ファイル、トラブル対処、CLIの詳しい説明です。初めて使う場合は、[READMEの「GUIでの使い方」](../README.md#guiでの使い方)から始めてください。

## 音声バックエンド

音声入出力にはCPALを使用し、既定は自動選択で、Windowsに登録ASIOドライバがある場合は直接ASIOを優先します。それ以外はCPAL経由でWindowsのWASAPI、macOSのCoreAudio、LinuxのALSAを使います。LinuxのビルドにはALSA開発パッケージ（Debian/Ubuntuでは`libasound2-dev`）が必要です。

CPALでは選択したサンプリングレートの共通f32/i32/i16形式を検査し、入力と出力の間に事前確保キューを使います。キュー遅延はDSP遅延とは別に表示します。別デバイスのクロック差は補正せず、キュー不足・満杯やデバイス異常を検出して停止します。実機の往復遅延と聴取品質は個別に確認してください。

```sh
cargo run --bin rust-low-latency-voice-changer-cli -- --list-devices
cargo run --bin rust-low-latency-voice-changer-cli -- --backend cpal --device "INPUT" --output-device "OUTPUT" --frames 512
```

CPALではデバイスを省略するとOSの既定入力・出力を使います。ASIOではドライバ名を指定してください。`--backend cpal` / `--backend asio`で明示選択できます。実行ファイルのビルド構成については[ビルド・開発](../DEVELOPMENT.md)を参照してください。

## はじめに

使用するサンプリングレートの音声入出力に対応したデバイスが必要です。実行ファイルを用意してから、次の手順で音声処理を開始します。WindowsのGUIにはWebView2 Runtimeが必要です。ソースコードから実行ファイルを作成する場合は、[ビルド手順](../DEVELOPMENT.md)を参照してください。

### 1. 起動する

`rust-low-latency-voice-changer-gui.exe` をダブルクリックします。コンソールウィンドウは開きません。メイン画面の **設定** を押すと、独立したOSウィンドウで設定できます。「音声デバイス」「声を変える」「雑音を減らす」「声を整える」のカテゴリから項目を選びます。変更後は **設定を保存** を押してください。保存した設定は次の音声開始時に使用します。設定ウィンドウは開いたままメイン画面を操作でき、閉じるときにも自動保存します。

### 2. デバイスと音声の接続を準備する

設定の **音声デバイス** で使う機器を選びます。ASIOでは **入出力デバイス**、CPALでは **入力デバイス** と **出力デバイス** を選びます。CPALで「システムの既定」を選ぶとOSの既定デバイスを使います。**モノラル（1 → 1）** と **ステレオ（1 → 1, 2）** はワンクリックで選べます。それ以外の割り当て・音声バックエンド・バッファサイズは **詳細設定** で調整できます。次回からは前回保存した設定を復元します。

**音声デバイス → サンプリングレート** で44.1・48 kHzから選びます（既定値48 kHz）。高レートはピッチ・フォルマント処理の品質検証が済むまで選択できません。入出力が共通して対応するレートが必要です。 選択したデバイスの対応レートを画面に表示します。標準バックエンドでは入力・出力それぞれと、同じ音声形式で共通して使えるレートを確認できます。表示対象はアプリで選択できる2種類です。チャンネルとバッファサイズの対応は開始時に確認します。ASIOではドライバー側も選択したレートに揃えてください。変更は次の音声開始時に反映されます。CLIでは `--sample-rate 44100` のようにHz単位で指定します。マイクの信号が届くチャンネルを指定するには、**入力チャンネル** を選び、**出力チャンネル** を1つ以上チェックしてください。選択したすべての出力へ同じ処理済み音声を送り、その他の出力は無音にします。既定はモノラル（1 → 1）です。チャンネルの変更は次の音声開始時に反映されます。CLIでは `--input-channel 2 --output-channels 1,2` のように指定できます。デバイスに存在しないチャンネルは開始時にエラーになります。

出力1をヘッドホンなどのモニター先、または録音・通話・配信に使う音声入力へ接続します。接続方法はデバイスや音声ルーティング機能によって異なります。アプリは外部の接続設定を自動変更しません。出力を入力へ戻す接続は避けてください。

Voicemeeter（Banana / Potato）や VB-Audio Matrix でルーティングする場合は、[接続ガイド](README.md) を参照してください（[Voicemeeter](voicemeeter.md) / [VB-Matrix](vbmatrix.md)）。

### 3. 設定を保存する

最初は **声の高さ** と **フォルマント** を中央のまま使い、その他の音声処理をオフにします。**設定を保存** を押してください。

### 4. 元の声で接続を確かめる

**音声を開始** を押し、マイクに向かって話します。「音声処理中」と表示され、出力先から元の声が聞こえることを確認してください。声の高さ（ピッチ）とフォルマントが両方0で、ランブルフィルター・ディエッサー・ノイズゲート・EQ・音量の自動調整・コンプレッサーがオフのときは、入力をそのまま返します。

### 5. 声を変える

**音声を停止** を押し、停止が完了して設定欄が操作できるようになったら、**声の高さ** を変更し、**設定を保存** を押してから **音声を開始** を押します。数値は **詳細設定** で指定できます。

- `3`：声を3半音高くする
- `-3`：声を3半音低くする
- `0`：元の声の高さに戻す

小数も指定できます。まずは小さな変更で試し、聞きながら調整してください。設定を変えるたびに停止 → 設定変更 → 設定を保存 → 音声を開始の順で操作します。

声の高さを保ってフォルマントを変えるには、フォルマントを独立して調整するをオンにし、**フォルマント** を変更します。`3` は声を明るく、`-3` は太くし、`0` は元のフォルマントを保持します。声の高さ（ピッチ）が0でも変更でき、声の高さ（ピッチ）と組み合わせても使えます。

## 設定項目

| 項目 | 使い方 |
| --- | --- |
| **音声バックエンド / Device** | 自動（ASIO優先）、CPAL、ASIOと、使用する入力・出力デバイスを選択します |
| **バッファサイズ（サンプル）** | 音声バッファのサイズ。既定512。デバイスが対応する値を指定します |
| **声の高さ（ピッチ）** | 声の高さ。−12〜+12半音、小数可。既定0 |
| **ピッチ変換方式** | **声の変換 → 詳細設定** で選びます。フェーズボコーダーは位相ロック（標準）とスペクトル位相同期、PVSOLA、PSOLAはTD-PSOLA＋フェーズボコーダー、TD-PSOLA＋リサンプリング、FD-PSOLAです。既定は位相ロック（標準） |
| **フォルマントを独立して調整する** | オンにすると、ピッチ変更時に元のフォルマントを保つ補正を行います。既定オン |
| **フォルマント** | 声の太さ・明るさの移動量。残響（リバーブ）とは別です。−12〜+12半音、小数可。既定0。非ゼロではフォルマントを独立して調整するをオンにします |

フォルマントを独立して調整するをオフにすると、声の高さとともにフォルマントも変わります。同じ声の高さ（ピッチ）でオン・オフを切り替えて聞き比べると違いを確認できます。オフのときにフォルマントを非ゼロにするとエラーになります。声の高さ（ピッチ）とフォルマントが両方0で、ランブルフィルター・ディエッサー・ノイズゲート・EQ・音量の自動調整・コンプレッサーがオフのときは、この設定にかかわらず元の音声を返します。

大きなフォルマント移動では声の幅や音量も変わり、歪みが生じる場合があります。まず±2〜3半音程度で聞きながら調整してください。

### ピッチ変換方式を聞き比べる

設定の **声の変換 → 詳細設定 → ピッチ変換方式** から、フェーズボコーダー、PVSOLA、PSOLAの3グループで方式を選びます。音声を停止し、方式を選んで保存してから、音声を開始してください。同じピッチ・フォルマント設定と音量で、母音の自然さ、子音、声の立ち上がりを聞き比べます。

**フェーズボコーダー** は、周波数成分の位相を保ちながら高さを変える方式です。

**位相ロック（標準）** は、周波数成分の位相関係を保ちながら高さを変えます。DSP遅延は合成ウィンドウ長で変わり、標準設定では512サンプル（48 kHzで約10.67 ms）です。

**スペクトル位相同期** は、直接スペクトル変換で主要な周波数成分の位相誤差を相関により推定して段階的に補正します。PVSOLAの時間伸縮・入力フレーム挿入とは別の方式です。CLIとINIでは `pvsola-sync` を指定できます。

**PVSOLA** は、位相ボコーダーで時間伸縮した音声に、相互相関で整列した入力フレームを周期的に挿入して位相をリセットし、最後に再生速度を変えてピッチを調整します。フォルマント補正には独自実装のケプストラム包絡を使います。DSP遅延は4608サンプル（48 kHzで96 ms）です。マイクからヘッドホンまでの目標10 msを超えるため、実際の会話で遅延を評価してください。

CLIでは `--pitch-algorithm phase-locked`、`pvsola`、`pvsola-sync`、`td-psola`、`td-psola-resampled`、`fd-psola` を指定できます。GUIでは「声の変換 → 詳細設定 → ピッチ変換方式」から方式を選び、同じピッチとフォルマント設定で聞き比べてください。設定を保存してから音声を開始すると反映されます。ピッチとフォルマント移動がともに0なら、方式にかかわらずこの段はビットを保ってバイパスします。

設定INIには `pitch_algorithm=phase-locked`、`pitch_algorithm=pvsola`、`pitch_algorithm=pvsola-sync`、`pitch_algorithm=td-psola`、`pitch_algorithm=td-psola-resampled`、`pitch_algorithm=fd-psola` のいずれかを保存します。このキーがない既存INIでは位相ロック（標準）（`phase-locked`）を使い、保存時にキーを追加します。不明な値は起動時のエラーになります。

**PSOLA** は、ピッチ周期に合わせて波形やスペクトルを重ねる方式です。

**TD-PSOLA＋フェーズボコーダー** は、入力波形の周期に沿って切り出した波形片を、変更後の周期で重ね合わせます。有声音はピッチマークを使って合成し、無声音は同じ遅延でコピーします。元の共鳴を保つ方式で、独立したフォルマント移動には後段のフェーズボコーダーを使います。GUIで選ぶとフォルマントを独立して調整するをオンにし、移動量は維持します。CLIでは `--pitch-algorithm td-psola --pitch 8 --formant preserve --formant-shift 2.53`、INIでは `pitch_algorithm=td-psola` を使います。フォルマントを独立して調整するをオフにするとエラーになります。

**TD-PSOLA＋リサンプリング** は独自実装の帯域制限リサンプラで高さとフォルマントを独立して調整します。有声音では周期同期グレイン、無声音では固定ホップの重ね合わせを使い、フォルマントの移動が0のときは入力を遅延コピーします。CLIでは `--pitch-algorithm td-psola-resampled`、INIでは `pitch_algorithm=td-psola-resampled` を使います。DSP遅延はウィンドウ設定で変わり、標準設定では5376サンプル（48 kHzで112 ms）です。

**FD-PSOLA** は、ピッチマークを中心に切り出した短時間フレームをFFTし、スペクトルを周波数方向に圧縮・伸張してから逆変換し、ピッチ同期で重ね合わせます。フォルマントを独立して調整するをオンにすると、平滑化したスペクトル包絡を保ちながら音源側を変換します。オフではスペクトル全体を変換するため、フォルマントもピッチに合わせて移動します。CLIでは `--pitch-algorithm fd-psola --pitch 7 --formant preserve`、INIでは `pitch_algorithm=fd-psola` を使います。DSP遅延はウィンドウ設定で変わり、標準設定では5376サンプル（48 kHzで112 ms）です。独立したフォルマント移動を有効にすると合成ウィンドウ長の遅延が加わります。機器・入出力バッファの遅延は別です。

TD-PSOLA＋フェーズボコーダーのDSP遅延はウィンドウ設定で変わり、標準設定では5376サンプル（48 kHzで112 ms、44.1 kHzで約121.9 ms）です。フォルマント移動が0以外なら合成ウィンドウ長が加わり、標準設定では5888サンプル（48 kHzで約122.7 ms）になります。波形の周期解析と隣接ピッチマークの確定を待つための遅延で、入出力バッファと機器の遅延は別です。現在の初版は低遅延モニターの目標を満たしていません。元の声のピッチを解析する範囲は80〜800サンプル周期（48 kHzで約60〜600 Hz）です。かすれ声、息声、急な発声変化では周期を誤認する場合があるため、母音、子音、声の立ち上がりを実際に聞いて比べてください。ピッチ0・フォルマント移動0では、ほかの方式と同じくこの段をビット単位でバイパスします。

バッファサイズ（サンプル）を小さくすると音声処理の周期が短くなりますが、処理が間に合わず音が途切れる場合があります。まず対応するサイズで安定して使えることを確認し、必要に応じて小さくしてください。

## ランブルフィルター

**ランブルフィルター（80 Hz）** をオンにすると、マイクの吹かれや、机・マイクスタンドの振動、空調の低い音を抑えます。80 Hz・12 dB/octのハイパスフィルターをゲートと声変換の前に適用します。既定はオフです。低い声の厚みも減るため、聞き比べながら使ってください。破裂音の低域成分は軽減できますが、マイク自体のクリップは修復できません。

CLIでは `--rumble-filter on` / `--rumble-filter off` で指定します。GUIでは停止 → 設定変更 → 設定を保存 → 音声を開始の順で切り替えます。設定はINIの `rumble_filter=true` / `false` に保存され、キーのない既存INIはオフとして読み込みます。先読みや音声バッファによる追加サンプル遅延はありませんが、周波数に応じた位相変化はあります。

## 声の音色（EQ）

声変換後、音量の自動調整・コンプレッサーの前に3バンドのピーキングEQを適用します。既定はオフです。通常の画面では「低域の厚み」「明瞭さ」「明るさ」を調整し、アプリ内ポップアップの **詳細設定** では各バンドの周波数（40〜16000 Hz）、ゲイン（−12〜+12 dB）、帯域幅（Q値、0.2〜8）とクリップ防止の出力調整（−18〜0 dB）を指定できます。

まず0から1〜3 dBずつ調整してください。こもる声は低域の厚みを下げ、言葉がぼやける場合は明瞭さを上げます。明るさを上げてサ行が刺さる場合は戻してください。スライダーの中央はそのバンドの補正なしです。詳細設定を閉じても全設定を保持し、通常の画面では詳細設定の周波数・Qを使ってゲインだけを変更します。

**EQを標準に戻す**は周波数と帯域幅（Q値）を既定値（250 Hz / Q 0.7、3000 Hz / Q 0.8、8000 Hz / Q 0.7）に戻し、ゲインとクリップ防止の出力調整を0にします。EQのオン・オフは保持します。設定変更は停止 → 変更 → 設定を保存 → 音声を開始の順で行います。オン・オフで比較するときは、ブースト時の減衰による音量差にも注意してください。

正のゲインの合計分をフィルター前に減衰し、音量の余裕を確保します。これはピーク値を保証するリミッターではありません。出力が小さく感じる場合は後段の音量の自動調整で調整できます。先読みや音声バッファによる追加サンプル遅延は0ですが、周波数に応じた位相変化はあります。EQオフ、または全ゲインとクリップ防止の出力調整が0のとき、この段はサンプルのビットを保ってバイパスします。

CLIでは例えば `--eq on --eq-band1 250,-3,0.7 --eq-band2 3000,2,0.8 --eq-band3 8000,1,0.7` を指定します。バンドの値は `周波数,ゲイン,Q`、クリップ防止の出力調整は `--eq-output -2`、GUIモードは `--eq-mode simple` / `pro` で指定します。モード値は互換性のため保存され、DSPの処理は共通です。GUIでは詳細設定をポップアップで開きます。

GUI設定INIには以下の6キーが必要です。既存INIにキーがない場合は、追加するかINIを削除して既定値で起動してください。

```ini
eq=off
eq_mode=simple
eq_band1=250,0,0.7
eq_band2=3000,0,0.8
eq_band3=8000,0,0.7
eq_output=0
```

## サ行の刺さり（ディエッサー）

「さ・し・す」が耳に刺さるときは、**サ行の刺さり軽減（ディエッサー）** の **有効** をオンにしてください。まずは 通常の画面の標準の位置で「さしすせそ」と話して聞き比べます。まだ刺さるときは「抑える強さ」を右へ、声がこもるときは左へ動かします。0では補正しません。設定は停止 → 変更 → 設定を保存 → 音声を開始の順で適用します。

アプリ内ポップアップの **詳細設定** では、分割周波数・しきい値・最大減衰量・アタック・リリースを調整できます。詳細設定を開閉しても音や数値は変わりません。通常の画面でも設定した詳細値を使い、抑える強さ（最大減衰量）だけを変更します。**ディエッサーを標準に戻す** は詳細値と強さを標準に戻し、オン・オフは維持します。

| 詳細設定 | 標準 | 範囲 | CLI |
| --- | --- | --- | --- |
| 分割周波数 | 5000 Hz | 2000〜12000 Hz | `--deesser-frequency` |
| しきい値 | −24 dBFS | −60〜0 dBFS | `--deesser-threshold` |
| 最大減衰量 | 6 dB | 0〜12 dB | `--deesser-range` |
| アタック | 0.5 ms | 0.1〜20 ms | `--deesser-attack` |
| リリース | 60 ms | 10〜500 ms | `--deesser-release` |

声変換と自動音量調整の後で、一次相補フィルターで分離した高域のRMS音量と全体に対する高域の比率を検出し、高域だけを動的に抑えます。最大減衰量は上限なので、常にその強さで減衰するわけではありません。先読み・追加バッファはなく、検出とゲインの応答時間および減衰中の位相変化があります。声やマイクによって効き方が変わり、息や明るい母音にも反応する場合があります。

CLIでは `--deesser on` / `--deesser off`、表示モードは `--deesser-mode simple` / `pro` を指定します。INIには `deesser`、`deesser_mode`、`deesser_frequency`、`deesser_threshold`、`deesser_range`、`deesser_attack`、`deesser_release` を保存します。新しいキーのない既存INIも、かんたんと標準の詳細値で読み込めます。オン・オフの既定はオフです。

## 音量の自動調整・コンプレッサー

**音量の自動調整** と **コンプレッサー** は、それぞれ個別にオン・オフできます。どちらも既定ではオフです。音量の自動調整は声の平均音量を目標に近づけ、コンプレッサーは大きな声を抑えて音量差を小さくします。両方を有効にすると、声の変換後に音量の自動調整、コンプレッサーの順で適用します。それぞれの **詳細設定** で調整でき、**標準に戻す** はその機能の詳細値だけを戻します。オフにしても設定値を保持します。

どちらかが有効な場合は、最後に−1 dBFSのピーク保護を適用します。自動音量調整だけが有効な場合、ピーク保護の回復時間は150 msです。両方オフの場合はサンプルのビットを保ってバイパスします。追加の音声バッファによる遅延はありません。

| 詳細設定 | 既定値 | 範囲・効果 | CLI |
| --- | --- | --- | --- |
| Target RMS dB | −20 dBFS | −36〜−6。会話の目標RMS音量 | `--level-target` |
| Max gain dB | +9 dB | 0〜18。小声の最大増幅量 | `--level-max-gain` |
| Activity floor dB | −50 dBFS | −90〜−30。これ以下では音量補正を更新しない。目標音量より低くする | `--level-floor` |
| Level response ms | 1500 ms | 100〜10000。音量補正の応答。長いほどゆっくり | `--level-response` |
| Comp. threshold dB | −12 dBFS | −36〜0。圧縮が始まるピーク音量。ニー幅は6 dB | `--compress-threshold` |
| Ratio | 3:1 | 1〜20。1ではコンプレッサーの圧縮なし | `--compress-ratio` |
| Attack ms | 5 ms | 0.1〜100。大声の圧縮速度 | `--compress-attack` |
| Release ms | 150 ms | 10〜2000。圧縮とピーク保護の回復速度 | `--compress-release` |

GUIの詳細値は保存・復元され、CLI指定は各項目だけを上書きします。設定変更は停止 → 変更 → 設定を保存 → 音声を開始の順です。CLIでは `--auto-level on|off` と `--compressor on|off` で個別に切り替えます。GUI設定INIには `auto_level`、`compressor` と、表の順に `level_target_db`、`level_max_gain_db`、`level_floor_db`、`level_response_ms`、`compress_threshold_db`、`compress_ratio`、`compress_attack_ms`、`compress_release_ms` を保存します。既存のINIにはこれらのキーが必要です。分離前のINIには `compressor=true` または `compressor=false` を追加してください。起動エラーが出た場合はキーを追加するか、INIを削除して既定値で起動してください。

```powershell
.\target\release\rust-low-latency-voice-changer-cli.exe --backend asio --device "ASIOデバイス名" --auto-level on
.\target\release\rust-low-latency-voice-changer-cli.exe --backend asio --device "ASIOデバイス名" --auto-level on --compressor on --level-target -18 --level-max-gain 6 --compress-ratio 4
```

無音では補正量を保持し、下限を超えるノイズも声として扱うため、発話判定の下限と最大増幅量を環境に合わせて調整してください。前段のゲートとも併用できます。音量補正の減衰は最大18 dB、後段のピーク保護は−1 dBFSで固定です。突発ピークは即時にゲインを下げるため、強い過渡音では波形に影響があります。入力やピッチ変換ですでにクリップした波形は復元しません。

この処理による追加のサンプル遅延は0です。応答時間はゲイン変化の速度であり、音声を遅らせる時間ではありません。ピッチ変換・ドライバ・ハードウェアの遅延は別に残ります。実機での聞き比べ・会話のしやすさ・総遅延は確認が必要です。

## 声の変換の処理ウィンドウ

**声の変換 → 詳細設定** で、位相ロック（標準）／スペクトル位相同期／TD-PSOLA＋フェーズボコーダー／TD-PSOLA＋リサンプリング／FD-PSOLAの解析ウィンドウ長と合成ウィンドウ長を変更できます。「ボコーダーのウィンドウ」と「PSOLAのウィンドウ」は独立した設定です。TD-PSOLA＋フェーズボコーダー／FD-PSOLAにフォルマント補正を組み合わせる場合も、PSOLA本体と後段のボコーダーのウィンドウ長を個別に調整できます。解析ウィンドウ長は1024・2048・4096・8192サンプル、合成ウィンドウ長は256・512・1024・2048サンプルから選びます。合成ウィンドウ長は解析ウィンドウ長以下にします。標準は解析ウィンドウ長2048、合成ウィンドウ長512サンプルです。

FD-PSOLAも長い過去側と短い未来側を持つ非対称の解析ウィンドウを使い、ピッチ位置を基準に短い合成ウィンドウで重ね合わせます。TD系では解析長が周期検出の範囲を変え、粒子の過去側と未来側の長さの比を解析長と合成長の比の平方根に合わせます。合計の長さを保ちながら両側をピッチ周期に追従させます。TD系の表示値は粒子の固定サンプル長ではありません。解析長と合成長が等しい場合は左右対称になります。

位相ロック（標準）／スペクトル位相同期のDSP遅延は合成ウィンドウ長です。PSOLA系には周期検出・隣接ピッチ位置の確定・粒子の重ね合わせを待つ遅延があり、合成ウィンドウを短くするだけでは低遅延になるとは限りません。短い合成ウィンドウでは低い声の粒子間に隙間が生じる場合もあるため、母音や子音を聞き比べて調整してください。画面のDSP遅延表示は入出力バッファーや機器の遅延を含みません。ピッチとフォルマントがともに0の場合は遅延なしのバイパスです。変更は保存後、次の音声開始時に反映します。PVSOLAは固定長です。

設定ファイルの `[gui]` セクションでは ボコーダーのウィンドウ長を `analysis_window` と `synthesis_window`、PSOLA本体のウィンドウ長を `psola_analysis_window` と `psola_synthesis_window` に保存します。項目がない場合は、それぞれ2048・512サンプルで読み込み、次の保存時に追加します。それぞれの段で合成長を解析長以下にしてください。段をまたいだ大小関係の制約はありません。不正な値を指定した場合はエラーになります。

CLIではボコーダーに `--analysis-window`／`--synthesis-window`、PSOLA本体に `--psola-analysis-window`／`--psola-synthesis-window` を指定します。例えば `--pitch-algorithm td-psola --pitch 7 --formant-shift 4 --psola-analysis-window 1024 --psola-synthesis-window 256 --analysis-window 8192 --synthesis-window 2048` とすると、PSOLAと後段のボコーダーに異なるウィンドウ長を使います。

## 停止と終了

**音声を停止** で音声処理を停止します。停止後にデバイスや声の設定を変更し、音声を開始で再開できます。処理中は設定欄が無効になります。

メインウィンドウを閉じると音声処理を停止して終了します。設定ウィンドウだけを閉じた場合は、設定を保存してメイン画面の操作を続けられます。ドライバの解放が完了するまで、閉じる処理に時間がかかる場合があります。

ウィンドウを閉じるときに、Device、サンプリングレート、バッファサイズ（サンプル）、声の高さ（ピッチ）、フォルマントを独立して調整する、フォルマントをGUIの実行ファイルと同じフォルダーの `settings.ini` に自動保存します。音声を開始していない変更も保存します。次回起動時に設定を復元しますが、音声処理は **音声を開始** を押すまで始まりません。

`sample_rate` を省略した既存のINIは48 kHzで読み込みます。

INIファイルはUTF-8で、次の形式です。`device` は未選択の場合に空欄になります。`preserve_formants` は `true` または `false` で指定します。

```ini
[gui]
backend=asio
output_device=
device=Example ASIO Device
frames=512
sample_rate=48000
pitch=0
formant_shift=0
preserve_formants=true
rumble_filter=false
deesser=false
deesser_mode=simple
deesser_frequency=5000
deesser_threshold=-24
deesser_range=6
deesser_attack=0.5
deesser_release=60
eq=off
eq_mode=simple
eq_band1=250,0,0.7
eq_band2=3000,0,0.8
eq_band3=8000,0,0.7
eq_output=0
gate=false
gate_threshold=auto
gate_attack_ms=5
gate_release_ms=80
auto_level=false
level_target_db=-20
level_max_gain_db=9
level_floor_db=-50
level_response_ms=1500
compress_threshold_db=-12
compress_ratio=3
compress_attack_ms=5
compress_release_ms=150
```

入力値が不正な場合や保存に失敗した場合はエラーを表示し、ウィンドウを開いたままにします。問題を直してから閉じ直してください。保存ファイルが壊れている場合は起動時にエラーを表示します。ファイルを修正するか削除すると、初期設定で起動できます。

## 困ったとき

| 状況 | 確認すること |
| --- | --- |
| Deviceの一覧にデバイスがない | 音声バックエンドの選択とOSのデバイス接続を確認し、ASIOの場合は対応ドライバをインストールします |
| 開始時にレートのエラーが出る | 入出力が対応するレートをアプリで選び直します。ASIOではドライバー側も同じレートに揃えます |
| バッファサイズ（サンプル）が非対応と表示される | 表示されたエラーを確認し、詳細設定で対応するサイズを指定します |
| 形式が非対応と表示される | 全入出力チャンネルが同じlittle-endian f32、i32、またはi16形式に対応するデバイスが必要です |
| 開始しても声が聞こえない | 選択した入力チャンネルにマイク音声が届いているか、選択した出力チャンネルが聞きたい出力先へ接続されているか確認します |
| 元の声と変えた声が重なる | デバイスの直接モニターや、未処理マイクを出力する別経路を確認します |
| 音が途切れる・異常で停止する | 表示されたエラーを確認し、対応範囲内でバッファサイズ（サンプル）を大きくして再開します |
| 声が歪む・揺れる | マイクの入力レベルを下げ、声の高さ（ピッチ）の変更幅を小さくして試します |

音声が出力先で聞こえるかは、実際にマイクに話して確認してください。

声の高さ（ピッチ）とフォルマントが両方0で、ランブルフィルター・ディエッサー・ノイズゲート・EQ・音量の自動調整・コンプレッサーがオフならDSPは遅延なしのバイパスです。ゲート・自動音量調整・コンプレッサーも追加サンプル遅延は0ですが、オンの場合は音量を変更します。ピッチまたはフォルマント変換では、位相ロック（標準）・スペクトル位相同期の合成ウィンドウ長（既定512サンプル）（48 kHzで約10.67 ms）、PVSOLAの4608サンプル（同96 ms）、PSOLA系の設定に応じた遅延（標準5376サンプル・同112 ms、TD-PSOLA＋フェーズボコーダー／FD-PSOLAでフォルマント移動を併用すると標準5888サンプル・約122.7 ms）のDSP遅延に、デバイスや音声の接続経路の遅延が加わります。バッファサイズ（サンプル）を小さくしても、このDSP遅延は減りません。ドライバのレイテンシは、マイクから出力先までの総遅延とは異なります。

## CLIでの操作

設定確認や時間を指定した実行には、補助ツールの `rust-low-latency-voice-changer-cli.exe` を使用できます。

```powershell
.\target\release\rust-low-latency-voice-changer-cli.exe --list-devices
.\target\release\rust-low-latency-voice-changer-cli.exe --backend asio --device "ASIOデバイス名" --inspect
.\target\release\rust-low-latency-voice-changer-cli.exe --backend asio --device "ASIOデバイス名" --pitch 3 --seconds 60
.\target\release\rust-low-latency-voice-changer-cli.exe --backend asio --device "ASIOデバイス名" --pitch 0 --formant-shift -3
```

`--seconds` を省略するとEnterで停止します。`--frames`、`--pitch`、`--formant preserve` または `--formant off`、`--formant-shift` で設定を指定できます。フォルマントシフトは−12〜+12半音、小数可、既定0です。詳細は `--help` を参照してください。

GUIにも `--backend`、`--output-device`、`--device`、`--frames`、`--pitch`、`--formant`、`--formant-shift` で起動時の値を渡せます。指定した項目は保存済みの値より優先し、指定しない項目は復元します。通常はウィンドウ内で設定できます。CLIはGUIの保存設定を使用・変更しません。
